# 移动端适配文档

本文档记录当前 Web 项目改造成 Android App 后，需要重点适配的功能范围、页面策略和验收标准。

## 1. 适配目标

移动端版本的目标不是重新开发一个独立 App，而是在现有 Vue 前端基础上，通过 Capacitor 打包为 Android 应用，并逐步优化手机端体验。

当前优先目标：

1. App 可以在 Android 模拟器或真机中稳定运行。
2. App 可以正常连接后端。
3. 核心学习流程在手机屏幕上可用。
4. 页面按钮、输入框、弹窗、文档预览不出现严重遮挡。
5. 后续可以继续复用 Web 端功能进行二次开发。

## 2. 当前技术方案

Android 端使用 Capacitor 承载现有 Web 前端：

```text
Vue 前端 -> Vite build -> Capacitor Android WebView -> FastAPI 后端
```

当前 Android 工程目录：

```text
frontend/android
```

Android Studio 需要打开该目录。

模拟器访问本机后端时使用：

```text
http://10.0.2.2:8000
```

真机调试时需要改成电脑局域网 IP。

## 3. 页面适配范围

### 3.1 主对话页面

主对话页面是移动端优先适配对象。

需要关注：

1. 对话内容区域可以正常滚动。
2. 输入框不会被系统键盘遮挡。
3. 发送按钮、上传按钮、设置按钮在手机屏幕上可点击。
4. 左侧栏或功能栏在小屏幕上不应长期占用宽度。
5. 会话列表、文档列表可以改为抽屉、弹窗或底部面板。

建议策略：

1. 桌面端保持原有左右布局。
2. 移动端主内容优先显示聊天区域。
3. 次要面板通过按钮打开。
4. 顶部操作按钮尽量图标化或收进更多菜单。

### 3.2 文档功能

文档相关功能需要确保移动端可以完成基本学习流程。

需要关注：

1. 文档列表在手机上可滚动。
2. 文档选择后可以正确加载。
3. 文档预览区域不要超出屏幕导致无法操作。
4. 上传文件入口在 Android WebView 中可正常触发文件选择。

建议策略：

1. 文档列表使用单列布局。
2. 文档详情页减少横向排布。
3. 预览内容允许纵向滚动。
4. 大尺寸文档预览可以使用缩放或独立查看区域。

### 3.3 Cheatsheet 功能

Cheatsheet 是移动端适配的重点功能之一。

需要关注：

1. 生成弹窗在手机屏幕上完整显示。
2. 页边距、列数、字号等配置项可以正常点击和输入。
3. 生成结果预览可以滚动查看。
4. 打印或导出 PDF 在 App 中需要避免依赖浏览器打印窗口。

建议策略：

1. 手机端预览优先保证可读性，不强制完全等同桌面排版。
2. 配置弹窗改为纵向表单。
3. PDF 导出优先使用后端生成文件，再由 App 下载或分享。
4. 双栏排版可以保留，但需要允许缩放或横向查看。

### 3.4 Mindmap 功能

Mindmap 在移动端需要重点处理触摸交互。

需要关注：

1. 节点内容在手机屏幕上不会过小。
2. 支持手指拖拽查看。
3. 支持缩放查看。
4. 工具按钮不遮挡画布。

建议策略：

1. 工具栏放在顶部或底部固定区域。
2. 画布区域尽量全屏。
3. 移动端减少复杂悬浮按钮。
4. 优先保证查看和缩放，编辑能力可以后续优化。

## 4. 移动端布局原则

移动端页面应遵循以下原则：

1. 单列优先，避免复杂左右分栏。
2. 主要任务优先显示，次要功能收起。
3. 按钮尺寸要适合手指点击。
4. 弹窗宽度适配屏幕，不应超出视口。
5. 输入框需要考虑软键盘弹出后的可见性。
6. 长内容优先纵向滚动。
7. 避免依赖 hover 交互。
8. 避免只适合鼠标操作的细小控件。

## 5. 后端连接注意事项

模拟器环境：

```bash
VITE_API_BASE_URL=http://10.0.2.2:8000 npm run build
npx cap sync android
```

真机环境：

```bash
VITE_API_BASE_URL=http://电脑局域网IP:8000 npm run build
npx cap sync android
```

后端启动方式：

```bash
cd backend
source venv/bin/activate
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

如果 App 显示网络连接失败，需要优先检查：

1. 后端是否正在运行。
2. `/health` 是否能在模拟器或真机访问。
3. API 地址是否使用了正确 IP。
4. 是否重新执行了 `npm run build` 和 `npx cap sync android`。
5. Android Studio 是否重新运行了新包。

## 6. 开发顺序建议

建议按照以下顺序推进移动端适配：

1. 确认 Android App 可以稳定连接后端。
2. 适配主对话页面。
3. 适配文档列表和文档查看。
4. 适配 Cheatsheet 生成弹窗和预览。
5. 适配 Mindmap 查看交互。
6. 处理下载、导出、分享等 App 能力。
7. 优化图标、启动页、应用名称和发布配置。

## 7. 基础验收标准

满足以下条件即可认为移动端基础适配通过：

1. App 可以在 Android Studio 中运行到模拟器或真机。
2. App 首屏不白屏、不崩溃。
3. App 可以连接后端并加载初始数据。
4. 对话请求可以正常发送并显示回复。
5. 文档相关页面可以进入并正常滚动。
6. Cheatsheet 或 Mindmap 至少一个核心功能可以正常使用。
7. 手机屏幕上主要按钮可以点击。
8. 输入框在键盘弹出后仍然可以正常使用。
9. 页面没有明显横向溢出或无法关闭的弹窗。

## 8. 后续增强方向

基础适配完成后，可以继续增强：

1. 使用 Capacitor 文件插件优化文件选择。
2. 使用 Capacitor Share 插件支持 PDF 分享。
3. 使用 Capacitor Filesystem 插件保存导出文件。
4. 增加移动端专用底部导航。
5. 增加 App 图标和启动页。
6. 配置正式 APK 或 AAB 打包签名。
